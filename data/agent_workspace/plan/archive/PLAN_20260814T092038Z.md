## Architecture and Approach
1. Uporabiti GitHub REST API z `per_page=100` in eksplicitno preveriti `Link` pagination oziroma število strani.
2. Za vsak rezultat pridobiti metadata in rekurzivno drevo privzete veje (`git/trees/{sha}?recursive=1`) ali enakovreden varen pregled vsebine.
3. Kandidatne testne poti identificirati s konvencijami imen; nato preveriti, ali vsebujejo dejanske teste (npr. `test(...)`, `it(...)`, `describe(...)`, `assert`, `unittest.TestCase`, `pytest` funkcije, Go `TestXxx`, Rust `#[test]`, ipd.).
4. Ločiti prisotnost testnih primerov od konfiguracije/CI in od dokumentacijskih omemb. Za večje ali nepopolno dostopne repozitorije uporabiti kloniranje oziroma API vsebino in zabeležiti mejo.
5. Rezultate zapisati v strojno preverljiv vmesni artefakt in nato v jedrnat končni odgovor v slovenščini.
